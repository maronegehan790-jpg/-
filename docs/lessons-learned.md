# دروس مشروع Zizo LMS

الملف ده بيتجمع فيه كل غلطة حصلت في المشروع، وسببها، وإزاي اتحلت.
الهدف: أي مشروع جديد بعد كده مايتكررش فيه نفس الغلط.

## إزاي تستخدم الملف ده

- الكلمة السرية: «دروس زيزو». لما تتقال بعد ما كل المراحل تخلص، المساعد يقرا الملف ده كله ويطلّع ملخص بسيط وقايمة مراجعة لأي مشروع جديد.
- في آخر كل Phase، بنضيف دروسها في قسم «سجل المراحل» تحت.

## الدروس لحد دلوقتي (التجهيز و Phase 1)

### 1. شغّل البرنامج من جوه فولدر المشروع
- الغلط: البرامج كانت بتشتغل من الفولدر اللي فوق المشروع (D:\ffff...) مش من جوه zizo-lms.
- النتيجة: `cd backend` فشل، و git قال "Not a git repository"، وأوامر /speckit ماظهرتش.
- الحل: `cd D:\ffffffffffffffffffffffffffffffff\zizo-lms` وبعدين `claude`. وفي البرنامج: File > Open Folder على zizo-lms نفسه.
- المرة الجاية: اختار أسماء فولدرات واضحة، وماتحطش المشروع جوه فولدر تاني من غير داعي.

### 2. كل برنامج بيدوّر على الأوامر في فولدر مختلف
- Claude Code بيقرا من `.claude/skills`، و Kiro من `.kiro/skills`، و Antigravity من `.agents/skills`.
- Spec Kit اتنزّل لـ Claude بس، فالأوامر ماظهرتش في البرامج التانية.
- المرة الجاية: وإنت بتعمل `specify init`، اختار البرنامج اللي هتشتغل بيه فعلاً.

### 3. فيه شباكين، وكل واحد له لغة
- PowerShell (علامته `PS D:\...>`): أوامر بس.
- شات المساعد (علامته `❯`): كلام عادي، أو أوامر قبلها علامة `!`.
- الغلط: اتكتب `! gh auth status` وكلام إنجليزي في PowerShell، فطلّع أخطاء.
- المرة الجاية: بص على العلامة قبل ما تكتب.

### 4. حساب GitHub الغلط
- كان فيه حسابين مسجلين، والنشط منهم كان بيقرا بس، فالرفع اترفض برسالة 403.
- الحل: `gh auth login` بحساب صاحب الريبو، وبعدين `gh auth setup-git`.
- المرة الجاية: اعمل `gh auth status` قبل أول push.

### 5. بعد أي Merge على GitHub، حدّث جهازك
- الـ Merge بيغيّر النسخة اللي على GitHub بس، مش اللي على جهازك.
- الحل: `git switch main` وبعدين `git pull`.

### 6. ملف feature.json
- ده عنوان بس، بيقول للأوامر إن الخطة في `specs/001-zizo-lms`.
- قايمة المهام نفسها (اللي خلص واللي لسه) في `tasks.md`.
- الملف متجاهَل في git (لونه رمادي)، فلازم يتعمل على كل جهاز بعد أي clone.

### 7. auto mode وقّف أداة Bash
- نظام الموافقة الأوتوماتيكية كان واقع، فمفيش ولا أمر اشتغل.
- الحل: تغيير الوضع بـ Shift+Tab.

### 8. حاجات صغيرة
- Docker متنزّل مش معناها إنه شغّال: لازم Docker Desktop يكون مفتوح (اتأكد بـ `docker ps`).
- ماتشغّلش `npm audit fix --force`: بيحدّث المكتبات بالعافية وبيكسر المشروع.
- تحذير npm عن allow-scripts: bcrypt و prisma و esbuild محتاجين سكريبتات التثبيت. على npm 11 شغّالة عادي، لكن npm 12 هيمنعها.
- إعداد الإنترنت في Kiro Web بيشتغل على الجلسات الجديدة بس.
- الجلسة اللي "اختفت" في Kiro Web كانت في تبويب Archived.

### 9. طريقة الشغل
- اعمل الفرع **قبل** ما تبدأ شغل المرحلة، مش بعده.
- فرع واحد لكل Phase، وبأسماء ثابتة (زي phase-02-foundational).
- كمّل الخطة الناقصة **قبل** الكود. في Phase 2 كان ناقص: جدول لروابط استعادة الباسورد، و Redis لعدّ المحاولات، وملف Docker، وقاعدة بيانات للاختبارات، وقاعدة بيانات في فحص GitHub.
- `/speckit-implement` يتشغّل على دفعات صغيرة، مش المشروع كله مرة واحدة، عشان المساعد مايتوهش.
- `/speckit-converge` يتشغّل بنطاق المرحلة الحالية بس، وإلا هيضيف المراحل الجاية كمهام مكررة.
- ماتصدقش "خلصت" من غير ما تشوف نتيجة الأوامر والاختبارات بعينك.
